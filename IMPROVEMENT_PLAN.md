# Проект улучшения EVS (Electronic Voting System)

Аудит проведён на клоне `monnommon/evs` (HEAD `969a5a4`): 62 теста проходят,
полный цикл «логин → создание опроса → генерация ссылки → голосование →
подтверждение → финализация → публичные результаты» проверен на живом
runserver. Каждый пункт ниже — проверенный факт с указанием файла/строки,
не впечатление.

## Фаза 2 — тайна голосования (суть претензии к «системе голосования»)

Сейчас администратор может восстановить бюллетень каждого голосовавшего:
в audit trail пишется `vote_id` + `option_ids` (`polls/views_public.py:29`), а
`AnonymousSession.fingerprint` хранится сырым хешем (`models.py:175`). Хеш-цепочка
доказывает целостность, но одновременно **расшифровывает волю каждого голоса**.

| # | Действие | Где | Затраты |
|---|---|---|---|
| 2.1 | Событие голосования в аудите логировать без `vote_id` и `option_ids` — только poll_id и отметка «голос учтён». Целостность подсчёта доказывает финальный `result_finalized` с tally | `views_public.py:25-31` | S |
| 2.2 | `GET /poll/{token}/confirm/` в JSON отдаёт выбранные пункты любому, у кого осталась ссылка (она живёт вечно) | `views_public.py:211-217` | В JSON — только `confirmed: true`; выбор показывать лишь в HTML голосовавшему (и то обсудить: ссылку пересылают) | S |
| 2.3 | Fingerprint в `AnonymousSession.fingerprint` не нужен для подсчёта — хранить его не на сессии, а только в Vote (уже есть), либо вообще убрать после 1.3 | `polls/models.py:101` | S |
| 2.4 | Тест на инвариант: «из полного audit trail + admin API невозможно восстановить бюллетень конкретного голоса» | `evs/tests.py` | M |
| 2.5 | Документально зафиксировать модель угроз в README (что защищает цепочка, а что — нет) | `README.md` | S |

## Порядок работ

```
Фаза 0 (день 1)     → безопасность деплоя + чистка: закрывает «упало и молчит»
Фаза 1 (дни 2-3)    → баги: каждое — маленький PR с тестом
Фаза 2 (дни 4-5)    → тайна голосования: главный репутационный фикс
Фаза 3 (дни 6-8)    → UX/вид: лендинг, тёмная тема, протокол печати
Фаза 4 (дни 9-12)   → массовая генерация ссылок, экспорт, CI
```

Половина фаз 0–1 — изменения по 1–5 строк. Фаза 2 — единственная, где
нужно обсуждение модели угроз с заказчиком до кода: без неё система честно
называется «опросник с аудитом», но не «тайное голосование».

## Критерии приёмки

1. `manage.py check --deploy` без warnings в prod-конфигурации.
2. Полный audit trail опроса не содержит содержимого бюллетеней (тест 2.4 зелёный).
3. Два одинаковых браузера на разных машинах голосуют без ложного отказа (тест на 1.3).
4. RU-интерфейс без английских строк (grep msgstr "" = 0).
5. CI зелёный на каждом PR.
